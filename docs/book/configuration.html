nextgsim Configuration Reference

This is the reference for the YAML configuration files of the four simulator binaries: nr-gnb, nr-ue, lte-enb and lte-ue. The key names, types and defaults below are read from the structs the files deserialize into:

BinaryStructSource
nr-gnbGnbConfignextgsim-common/src/config.rs
nr-ueUeConfig (and SessionConfig)nextgsim-common/src/config.rs
lte-enbEnbConfignextgsim-enb/src/config.rs
lte-ueLteUeConfignextgsim-lte-ue/src/config.rs

When this page and a struct disagree, the struct wins: every field carries a doc comment with the full rationale, which this page shortens.

Configuration File Format

Configuration files are YAML, loaded once at startup.

nr-gnb -c config/gnb.yaml
nr-ue  -c config/ue.yaml
lte-enb -c config/enb.yaml
lte-ue  -c config/lte-ue.yaml

Format rules that are easy to get wrong:

  • nci is an integer. Write it unquoted, in hex or decimal (nci: 0x000000010). A quoted '0x000000010' is a string and is refused.
  • Keys are byte arrays. key and op are 16 bytes and amf is 2 bytes, written as YAML sequences (amf: [0x80, 0x00]), not hex strings.
  • supi is a mapping, { supi_type: Imsi, value: "999700000000001" }, not an imsi-... string. (The -i/--imsi command-line override does take the imsi- form.)
  • Enum spellings are the Rust variant names: op_type: Opc or Op; session type: Ipv4, Ipv6, Ipv4v6, Unstructured or Ethernet.
  • plmn / hplmn need all three keys: mcc, mnc and long_mnc.
  • An S-NSSAI is { sst: 1, sd: null } or { sst: 1, sd: [0, 0, 1] }.
  • A key not listed here is ignored silently (no struct sets deny_unknown_fields), so a misspelt optional key has no effect.

“Required” below means the file is refused without the key. A key marked optional takes the default shown when absent.

The shipped files in config/ all parse and are the best starting point:

FileUse
gnb.yaml, ue.yamlgNB and UE on the nextgcore Docker network (172.23.0.0/24)
gnb-docker.yaml, ue-docker.yamlMounted by docker/docker-compose.yml
gnb-local.yaml, ue-local.yamlgNB and UE on the host (RLS over 127.0.0.1) against the Docker AMF

gNB Configuration

Example

Cut down from config/gnb.yaml; it parses as it stands.

nci: 0x000000010            # NR Cell Identity (36-bit)
gnb_id_length: 32           # 22..32
plmn:
  mcc: 999
  mnc: 70
  long_mnc: false
tac: 1
nssai:
  - sst: 1
    sd: null
amf_configs:
  - address: 172.23.0.5     # an IP address or a hostname
    port: 38412
sctp_backend: userspace     # or kernel
link_ip: 172.23.0.100       # RLS (radio) socket
ngap_ip: 172.23.0.100       # N2
gtp_ip: 172.23.0.100        # N3
ignore_stream_ids: false
upf_addr: 172.23.0.7
upf_port: 2152
si_broadcast_period_ms: 80

Troubleshooting

  1. The file is refused. The error names the key and line. The usual causes are a quoted nci, hex-string keys, an imsi-... string for supi, a missing long_mnc, or other spellings of the enum values (IPv4, OPC).
  2. PLMN mismatch. plmn (gNB) must match hplmn (UE) and the core.
  3. NSSAI mismatch. The UE’s configured_nssai must include a slice the gNB’s nssai supports.
  4. Authentication failure. key, op and op_type must match the subscriber in the core’s database.
  5. No NG Setup against a real AMF. The default sctp_backend: userspace is SCTP over UDP. Build with --features kernel-sctp and set sctp_backend: kernel.
  6. gNB not found. gnb_search_list must contain the gNB’s link_ip.
  7. A paired setting differs. as_security_enabled, dl_arfcn, paging_default_cycle_frames and rlc_am_psis must agree between gNB and UE.

Enable debug logging with RUST_LOG:

RUST_LOG=debug nr-ue -c config/ue.yaml
RUST_LOG=nextgsim_nas=trace nr-ue -c config/ue.yaml
